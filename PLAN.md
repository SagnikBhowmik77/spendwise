# Spendwise: build plan (real data only)

Source brief: "Personal Finance Tracker.pdf" (goal, tech stack, 14-day schedule, 9 use cases, bonus ideas).

## Ground rules (same as Hopin; re-read before every step)

1. **Nothing simulated.** No demo accounts, no fake seed transactions, and no sample charts filled with made-up numbers. A new user starts with zero transactions, and every chart shows an honest empty state until real entries exist. If a feature is missing its key (for example, email reports without SMTP), the API says it isn't configured and the UI shows that.
2. **No fake text in the app** to make something look finished.
3. **One step at a time.** Each step is: build → test against the real service → report what was verified → wait for your go-ahead.
4. **Keys are requested before the step that needs them.** You create the accounts.
5. **Backend, database and APIs first**, then the frontend.
6. **Free tiers only.** Anything paid gets flagged before it is used.

## Decided (2026-10-23)

MongoDB Atlas (as the brief says), our own JWT auth, Claude builds the full frontend after the backend steps, INR only (stored as integer paise, shown with the en-IN Intl API).

**Scope:** every item in the brief's 2-week schedule plus **all** bonus features (CSV/PDF export, monthly email reports, recurring transactions, PWA, light/dark mode). After that, you add your own feature list.

Name: **Spendwise** (chosen 2026-10-23). Atlas cluster: Cluster0 (free tier, AWS), database `spendwise`.

Local ports: API 8730, client 5200 (Vite proxies `/api` to the API in dev).

## Do we need datasets?

**No.** A finance tracker's data is the user's own income and expenses, which they enter themselves. Importing a Kaggle dataset as "your transactions" would be fake data. Tests run against a real throwaway MongoDB instance (mongodb-memory-server), never the production database.
